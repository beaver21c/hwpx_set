# 사용자 양식으로 만들기 (양식 보존)

사용자가 **쓰던 한글 양식(.hwpx)** 을 가지고 있으면 이 길이 낫다. 내장 서식은 관례를
옮겨 적은 것이라 기관 양식과 미세하게 다르고, 한글의 자동 글머리표·번호매기기는
애초에 옮겨지지 않는다.

## 왜 다른가

| | 내장 서식(프로파일) | 양식 보존(꾸러미) |
|---|---|---|
| 서식의 출처 | `profile.json`을 읽어 새로 지음 | 양식 파일을 그대로 씀 |
| `header.xml` | 통째로 새로 씀 | **한 바이트도 안 건드림** |
| 자동 글머리표·번호매기기 | 잃음 | 그대로 삶 |
| 쪽 설정·표지·머리말 | 새로 지음 | 그대로 삶 |
| 마커 | 프로파일이 정함 | 양식에서 읽어 냄(양식마다 다름) |

## 절차

### 1. 양식을 해부해 꾸러미를 만든다

```bash
python scripts/formkit.py 양식.hwpx -o 꾸러미/ --name "정책보고서틀"
```

`해부보고서.md`가 나온다. **읽는다.** 레벨이 뜻대로 잡혔는지, 마커가 무엇인지,
'임의로 정했다'는 말이 있는지 본다.

### 2. 마커를 확인한다

```bash
python 꾸러미/build_form.py --markers
```

마커는 양식마다 다르다. **이 스킬의 `□ ○ - ·`를 그대로 쓰지 않는다.**
표에 '한글이 자동으로'라고 적힌 레벨은 마커만 쓰고 본문에 기호를 또 적으면 안 된다.
이중으로 찍힌다.

### 3. 본문을 쓴다

집필 규칙(계층 균형·개조식·머릿글·각주)은 이 스킬의 것을 그대로 지킨다.
바뀌는 것은 마커뿐이다. 표·각주 문법은 같다.

```
| 구분 | 값 |       표(첫 행이 머리행)
[표: 제목]          표 제목
{cols=30,35,35}     열 너비 백분율
앞말[^1]            각주 번호 자리
[^1]: 내용          각주 내용
```

### 4. 검사하고 만든다

```bash
python 꾸러미/build_form.py 원고.md --check-only
python 꾸러미/build_form.py 원고.md -o 결과.hwpx
```

검사는 세 층이다. 2층(양식에 없는 스타일 번호, 이중 기호)에 걸리면 **파일을 만들지
않는다.** 그 경고를 끄려 하지 말고 본문이나 `form.json`을 고친다.

### 5. 사용자에게 알린다

만든 문서의 최종 모양은 **한글에서 열어야** 확인된다. 그 사실을 숨기지 않는다.

## 이미 있는 문서를 이 양식으로

사용자가 내용만 든 hwpx를 주면 처음부터 다시 쓰지 않는다.

```bash
python 꾸러미/read_hwpx.py 받은문서.hwpx -o 원고.md --report 추정근거.md
```

`추정근거.md`를 **읽는다.** 단계를 무엇으로 갈랐는지(기호·번호·글자 크기) 적혀 있다.
틀렸으면 `원고.md`의 마커를 고친다. 그런 뒤 4번으로 간다.

**그림은 읽지 못한다.** `[그림 자리]`로 남는다. 조직도·절차도라면 원본 그림을 직접
보고 이 스킬의 도식 문법으로 옮겨 적은 뒤 **사용자에게 맞는지 물어본다.**

## 마커가 뜻과 다를 때

`form.json`의 `levels`를 고친다.

| 키 | 뜻 |
|---|---|
| `marker` | 입력에서 이 레벨을 부르는 기호 |
| `write_marker` | 기호를 본문 텍스트에 적어 넣나(한글이 붙이면 `false`) |
| `numbering` | 도구가 번호를 매기나. 한글이 매기면 `null` |
| `marker_invented` | 근거 없이 도구가 정해 준 마커인가 |

`style`·`para`·`char` 번호는 **임의로 바꾸지 않는다.** 양식에 없는 번호를 쓰면
2층 검사가 멈춘다.

## 하지 말 것

- `template.hwpx`를 고치지 말 것
- 검사 경고를 끄지 말 것
- 마커를 짐작하지 말 것. `--markers`로 확인할 것
- 되돌리기 결과를 확인 없이 그대로 쓰지 말 것. 추정이다
