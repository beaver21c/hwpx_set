# 계층 균형 규칙

레벨 간 균형이 깨지면 보고서 구조가 어색해진다. 다음 규칙을 반드시 지킨다.

## 균형 규칙

- `##`(숫자) 아래에 **네모 2개 이상** 필수
- `□`(네모) 아래에 **원 2개 이상** 필수
- `○`(원) 아래에 **하이픈 2개 이상** 필수
- `-`(하이픈) 이하(점·참고)는 균형 규칙 **미적용**. 필요한 만큼만 사용

하이픈 아래에 점이 1개만 있어도 무방하며, 없어도 된다.

## 옳은 구조

```
## 배경 및 필요성
□ 【배경 1】 정책 수요 변화
○ (1) 고령화 심화
- 65세 이상 인구 비율 20% 초과
- 돌봄 서비스 수요 급증
○ (2) 1인 가구 증가
- 1인 가구 비중 35% 도달
- 사회적 고립 위험 상승
· 고독사 위험군 모니터링 대상 전년 대비 2.3배 확대
□ 【배경 2】 기술 환경 변화
○ (1) AI 도입 확산
- …
- …
○ (2) 데이터 인프라 성숙
- …
- …
```

## 피해야 할 구조

### 네모 아래 원이 1개만 있는 경우

```
# 잘못된 예
□ 【배경 1】 정책 수요 변화
○ (1) 고령화 심화
- …
- …   ← 다음 네모로 바로 넘어감 → 원이 1개뿐
□ 【배경 2】 기술 환경 변화
```

해결: 원을 보강하여 2개 이상으로 만들거나, 네모를 다른 네모와 통합한다.

### 원 아래 하이픈이 1개만 있는 경우

```
# 잘못된 예
○ (1) 고령화 심화
- 65세 이상 인구 비율 20% 초과   ← 하이픈 1개로 끝남
○ (2) 1인 가구 증가
```

해결: 하이픈을 보강하거나, 그 원을 상위 원에 통합한다.

### 숫자 아래 네모가 1개만 있는 경우

```
# 잘못된 예   ← # 배경 및 필요성
□ 【배경 1】 정책 수요 변화
○ …
○ …   ← # 선행 연구  # 네모가 1개뿐
```

해결: 소절 자체를 재설계한다. 다른 절과 통합하거나 네모를 추가한다.

## 균형 검증 순서

본문을 다 쓴 뒤 다음 순서로 점검한다.

1. 모든 `##`(숫자) 직하의 네모(`□`) 개수가 2 이상인지 확인
2. 모든 네모 직하의 원(`○`) 개수가 2 이상인지 확인
3. 모든 원 직하의 하이픈(`-`) 개수가 2 이상인지 확인
4. 점(`·`)·참고(`5`)는 개수 검증 불필요

균형이 깨진 부분이 발견되면 다음 중 하나를 선택한다.

- **보강**: 누락된 하위 항목을 추가로 작성
- **통합**: 부족한 항목을 인접한 상위·동급 항목과 합쳐 재구성
- **재설계**: 해당 섹션의 구조 자체를 다시 잡음

특히 미리보기 단계에서 균형이 자주 깨지므로, 사용자에게 보여주기 전에 반드시 검증한다.
