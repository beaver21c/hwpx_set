# 도식 상세

조직도·체계도·절차도·전략체계도를 한글에서 **편집 가능한 표**로 그린다. 본문 아무 곳에나
`:::diagram` 으로 시작해 `:::` 로 끝나는 블록을 넣으면 된다(앞뒤에 빈 줄).

## 네 가지 유형

### 조직도·체계도 (`type=org`)

**들여쓰기 2칸**이 한 단계 아래다. 도식 블록 안에서만 들여쓰기가 계층을 뜻한다.

```
:::diagram type=org title="추진 체계"
총괄
  기획부
    기획팀
    예산팀
  운영부
:::
```

같은 단계 상자가 8개를 넘으면 **세로 목록형으로 자동 전환**된다(폭이 늘지 않는다).
직접 지정하려면 `layout=side`, 가로를 고집하려면 `layout=wide`.

### 절차도 (`type=flow`)

```
:::diagram type=flow title="처리 절차"
접수 → 검토 → 심의 → 통보
:::
```

세로 배치는 `direction=down`. 화살표는 `→` `->` `=>` `>` 아무거나 인식한다.

### 격자 (`type=matrix`)

첫 행·첫 열이 제목 칸이 된다.

```
:::diagram type=matrix title="역할 분담"
| | 중앙 | 지방 |
| 기획 | 본부 | 지역본부 |
| 집행 | 사업단 | 현장사무소 |
:::
```

### DB 구성도 (`type=db`)

`[이름]`이 테이블, 들여쓴 줄이 필드다. 필드 앞의 `*`는 기본키, `+`는 외래키.
화살표가 든 줄은 관계이며, **붙어 있는 두 테이블 사이**에만 그려진다.

```
:::diagram type=db title="지원사업 DB 구성"
[회원]
  *회원ID
  이름
[신청]
  *신청ID
  +회원ID
  신청일
회원 → 신청
:::
```

### 전략체계도 (`type=strategy`)

미션·비전·핵심가치·전략방향·전략과제가 단으로 쌓이는, 공공기관 경영전략 체계도의 정형이다.
**왼쪽에 단 이름, 오른쪽에 그 단의 칸들**을 `|`로 나눠 쓴다.

```
:::diagram type=strategy title="경영전략 체계도"
미션 | 국민의 삶의 질 향상에 기여한다
비전 | 누구도 돌봄에서 빠지지 않는 지역사회
핵심가치 | 존중 | 연계 | 형평 | 신뢰
4대 전략방향 | 대상자 발굴 | 서비스 연계 | 전달체계 | 돌봄 현장
12대 전략과제 | 과제1 | 과제2 | 과제3 | 과제4
| 과제5 | 과제6 | 과제7 | 과제8
:::
```

- **라벨 없이 `|`로 시작한 줄은 위 단의 다음 줄**이다(라벨 칸이 그만큼 세로로 늘어난다)
- 칸이 하나뿐인 단(미션·비전)은 가로 전체를 차지한다
- 연결선은 자동이다. 갈래가 갈리는 곳(1칸 → 4칸)에만 가로선이 생기고, 칸 수가 같으면
  세로선만 내려온다
- `label_width=24`(mm)로 라벨 열 폭을 조절한다

## 색·선

상자 이름 뒤에 `{ }`로 적는다. 원본 도식의 색을 옮겨 담을 때 쓴다.

```
대표 {fill=#C00000 color=#FFFFFF}
  기획부 {fill=#2E75B6 color=#FFFFFF}
  감사실 {fill=#FFF2CC border=#BF8F00 link=dash link_color=#808080}
```

| 속성 | 뜻 |
|---|---|
| `fill` | 상자 채움색 |
| `color` | 글자색 |
| `border` | 테두리색. `none`이면 상자 없이 **글자만**(전략체계도의 수치 칸처럼) |
| `link` | 이 상자로 내려오는 연결선 종류(`dash` `dot` `longdash` …). `none`이면 안 그린다 |
| `link_color` | 그 연결선의 색 |

- 색은 `#RRGGBB` 또는 `#RGB`. 알아볼 수 없는 값은 무시하고 기본색을 쓴다(생성은 실패하지 않는다)
- 블록 첫 줄에 쓰면 그 도식 전체에 적용된다:
  `:::diagram type=org box_fill=#F2F2F2 root_fill=#404040 line_color=#808080 line_style=dash`
- 한글 표는 한 셀의 네 변이 같은 선 종류를 공유한다. 그래서 `link=dash`는 그 자식으로
  내려가는 **구간**에 적용되고, 형제가 함께 쓰는 가로선 전체가 점선이 되지는 않는다

## 이미 있는 도식을 옮길 때

### Mermaid·SVG·HTML 파일이면 도구가 읽는다

```bash
python scripts/capture.py 조직도.svg --title "조직 체계"      # 도식 블록만 출력
python scripts/capture.py 조직도.mmd --hwpx 조직도.hwpx       # 문서까지 한 번에
```

색과 점선은 **원본에 적힌 값 그대로** 가져온다. 연결선이 없는 SVG는 상자의 높이로 계층을
추정하고 그 사실을 경고로 알린다 — 반드시 눈으로 확인한다.

### 그림·캡처(PNG·스캔)뿐이면 에이전트가 받아쓴다

도구는 픽셀을 읽지 못한다. 이때는 **직접 그림을 보고** 위 형식으로 옮긴다.

1. 상자의 계층·순서를 읽어 블록으로 쓴다. 어느 단계인지 확실하지 않으면 **추정하지 말고
   사용자에게 묻는다**
2. 색은 원본과 비슷한 `#RRGGBB`로 적는다. 정확한 값이 필요하면 사용자에게 원본 SVG나
   색상 코드를 요청한다
3. 완성한 블록을 사용자에게 **보여 주고 확인받은 뒤** 본문에 넣는다

받아쓴 결과는 그냥 텍스트라, 틀린 곳은 한 줄 고치면 된다.

## 표로 재현되지 않는 것

둥근 모서리, 곡선·대각선 연결선, 화살촉, 그림자·겹침, 회전한 글자, 아이콘. 이런 요소가
핵심인 도식은 표로 옮기기에 맞지 않는다. 원본 그림을 `![](경로.png)`로 넣는 편이 낫다.
