# 각주

## 쓰는 법

번호가 들어갈 자리에 `[^라벨]`, 내용은 `[^라벨]: …` 줄.

```
□ 【쟁점 1】 노인 빈곤의 구조
○ 노인 빈곤율은 40.4%로 OECD 회원국 가운데 가장 높다[^1]
- 65세 이상 1인 가구는 전체 평균 소득의 절반에 못 미친다[^2]

[^1]: 통계청(2024), 「가계금융복지조사」.
[^2]: 보건복지부(2025), 『노인실태조사』, 87쪽.
```

- 내용 줄은 **문서 어디에 적어도 된다.** 문단 바로 아래여도 되고 글 끝에 모아도 된다
- 내용 줄은 본문에 나오지 않는다
- **라벨은 이름표일 뿐이다.** 인쇄되는 번호는 한글이 문서 순서대로 매긴다.
  `[^1]`처럼 숫자로 쓰되 실제 순서와 어긋나면 검사가 알려 준다
- 한 문단에 여러 개를 달아도 각각 제자리에 들어간다

한글의 **진짜 각주**다. 쪽 아래에 구분선과 함께 붙고, 문단을 옮기거나 각주를 지우면
번호가 다시 매겨진다. 본문에 `1)`을 손으로 적는 것과 다르다. 글씨는 **8pt 회색**.

## 번호를 놓는 자리

### 1. 앞말에 붙여 쓴다

번호 앞에 빈칸을 두지 않는다. 각주는 **바로 앞의 말**에 대한 것이라는 표시다.

```
○ 재정 지출은 GDP의 12%였다[^1]      ← 맞다
○ 재정 지출은 GDP의 12%였다 [^1]     ← 빈칸
```

### 2. 문장 전체의 근거이면 마침표 앞

국내 학술지·정부 보고서의 관행이다. 시카고 방식(마침표 뒤)과 다르다.

```
○ 이 추세는 2010년대 내내 이어졌다[^2].     ← 맞다
○ 이 추세는 2010년대 내내 이어졌다.[^2]     ← 시카고 방식
```

개조식 단문은 애초에 온점을 찍지 않으므로 문장 끝에 그냥 붙이면 된다(`…높다[^1]`).

### 3. 인용 자체가 각주 대상이면 따옴표 안

각주가 무엇을 가리키는지에 따라 자리가 갈린다.

```
○ 보고서는 "노인 빈곤은 구조적 문제다[^3]"라고 표현했다
   └ 인용문 자체의 출처·근거 → 닫는 따옴표 안

○ 이 표현은 "구조적 문제"[^4]라는 진단과 맥을 같이한다
   └ 인용을 쓴 문장 쪽의 근거 → 따옴표 밖
```

도구는 이 둘을 구분하지 못하므로 검사하지 않는다. 인용문의 출처를 다는 경우가
대부분이므로, 헷갈리면 **따옴표 안**이다.

### 4. 낱말 하나면 그 낱말 뒤

무엇에 대한 근거인지가 자리로 드러난다. 문장 끝까지 끌고 가지 않는다.

```
○ 노인장기요양보험[^4]과 기초연금[^5]은 도입 시기가 다르다
```

### 5. 제목·표·도식에는 달지 않는다

- **제목**(`#`, `##`)에 달면 목차에 번호가 딸려 들어간다. 그 아래 첫 문단에 단다
- **표 안**·**도식 상자 안**에는 들어가지 않는다. 표·도식 **아래 문단**에 달거나,
  표 아래에 `※ ` 줄로 주석을 붙인다

## 무엇을 각주로 하는가

| 본문에 그냥 쓸 것 | 각주로 뺄 것 |
|---|---|
| 논지 전개에 필요한 내용 | 자료 출처(기관·연도·자료명·쪽수) |
| 독자가 반드시 읽어야 할 수치 | 용어 정의, 범위 한정, 산출 방식 |
| | 본문 흐름을 끊는 부연 |

- 본문에 `(통계청, 2024)`처럼 괄호 출처를 적지 않는다. 각주로 뺀다
- 각주가 본문보다 길어지면 본문으로 올리거나 별도 항목으로 뺀다
- **출처를 지어내지 않는다.** 확인한 자료만 적고, 확인하지 못했으면 `[확인 필요]`로
  남겨 사용자에게 묻는다. 존재하지 않는 문헌을 각주로 다는 것이 이 도구에서 나올 수
  있는 가장 나쁜 산출물이다

## 검사가 잡는 것

`[경고:footnote]` — 번호 자리

| 상황 | 알려 주는 말 |
|---|---|
| 번호 앞에 빈칸 | 앞말에 붙여 쓸 것 |
| 마침표 뒤에 번호 | 마침표 앞에 붙일 것 |
| 제목에 각주 | 본문 문단으로 옮길 것 |
| 문단 맨 앞에 번호 | 근거가 되는 말 뒤에 붙일 것 |
| 라벨 숫자 ≠ 실제 번호 | 문서 순서로는 N번째 각주 |

`[경고:parser]` — 내용이 어긋난 경우

| 상황 | 도구의 처리 |
|---|---|
| `[^1]`을 썼는데 내용 줄이 없음 | 본문에 `[^1]`을 **그대로 남기고** 알려 준다 |
| 내용 줄만 있고 본문에서 안 부름 | 각주를 만들지 않는다 |
| 같은 라벨을 두 번 부름 | 각주 **두 개**가 만들어진다(한글에는 각주 재사용이 없다) |
| 같은 라벨의 내용 줄이 두 번 | 뒤엣것을 쓴다 |

## 서식 바꾸기

`profile.json`의 `footnote` 블록. 기본값은 8pt 회색(`#808080`)이다.

```json
{ "footnote": { "size_pt": 9, "color": "#595959" } }
```

`name`(`각주`)·`eng_name`(`Footnote`)은 **바꾸지 않는다.** 한글이 각주 스타일을 이
이름으로 찾는다.

기관 지침이 시카고 방식(마침표 뒤)이면 검사 기준을 바꾼다.

```json
{ "rules": { "footnote_position": "after_period" } }
```
