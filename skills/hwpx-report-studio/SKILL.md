# HWPX 정책 보고서 (hwpx-studio 엔진)

KIHASA(한국보건사회연구원) 스타일의 한글(.hwpx) 정책 보고서를 만든다. 작성자는 사회과학
연구자, 독자는 일반 국민·공무원·정책 실무자이며 문서 성격은 연구·정책 보고이다.

본문은 **마커를 붙인 평범한 텍스트**로 쓴다. 파이썬 코드를 고치지 않는다.

## 핵심 원칙

- **사전 미리보기 필수**: 본문 전체를 한 번에 쓰지 않는다. 항상 10~20 항목 분량의 초안을
  먼저 보여주고 사용자 승인을 받는다
- **서식은 프로파일에서만**: 글꼴·크기·색·여백은 `profile.json`에 있다. 사용자 지시가 없으면
  건드리지 않는다. 본문 파일에는 서식을 쓰지 않는다
- **자동 부여 기호 금지**: 마커(`□ ○ - · ※`)와 자동 번호(`Ⅰ. 1.`)는 도구가 붙인다.
  본문 텍스트에 겹쳐 쓰지 않는다
- **사실 기반 서술**: 존재하지 않는 논문·통계·법령 인용 금지. 확인 못 한 수치는 `[확인 필요]`
- **검사 결과를 무시하지 않는다**: `lint`가 내는 경고는 대부분 실제 구조 문제다

## 먼저 물을 것 — 기관 양식이 있는가

사용자가 **쓰던 한글 양식(.hwpx)** 을 가지고 있으면, 이 스킬의 내장 서식으로 만들지
말고 그 양식을 보존하는 길로 간다. 내장 서식은 KIHASA 관례를 옮겨 적은 것이라
기관 양식과 미세하게 다르고, 한글의 **자동 글머리표·번호매기기**는 애초에 옮겨지지
않는다.

```bash
python scripts/formkit.py 양식.hwpx -o 꾸러미/
python 꾸러미/build_form.py 원고.md -o 결과.hwpx
```

꾸러미는 양식 파일을 **템플릿으로 그대로 두고** 본문만 갈아 끼우므로 글꼴·자동
글머리표·번호매기기·쪽 설정이 원본 그대로다. 마커는 양식마다 다르니
`python 꾸러미/build_form.py --markers`로 확인한 뒤 그 마커로 본문을 쓴다.

**줄머리 기호를 누가 붙이는지 확인한다.** 한글이 자동으로 붙이는 양식이면 본문에
기호를 적지 않고, 아니면 도구가 적는다. 해부가 반대로 볼 수 있으므로 마커 표를 보고
다르면 `--bullets hangul` / `--bullets text`로 바꾼다.
자세한 절차는 `reference/form-bundle.md`.

사용자가 **내용만 든 hwpx**를 주었을 때도 처음부터 다시 쓰지 않는다.

```bash
python 꾸러미/read_hwpx.py 받은문서.hwpx -o 원고.md --report 추정근거.md
```

양식이 없거나 사용자가 이 스킬의 서식을 원하면 아래 절차로 간다.

## 표준 작업 절차

여섯 단계를 순서대로 진행한다. 각 단계에서 승인을 받기 전에 다음으로 넘어가지 않는다.

1. **목차 구성안 제시** — 로마자(장)·숫자(절) 수준의 목차안을 2~5줄로 제시하고 확인받는다
2. **반 페이지 미리보기** — 아래 레벨 체계·계층 균형·머릿글 규칙에 맞춰 10~20 항목 분량의
   본문 초안을 작성해 화면에 보여주고 승인받는다
3. **본문 완성** — 승인된 골격에 나머지를 채워 `input.md`로 저장한다
4. **검사** — `python scripts/build.py input.md -o 보고서.hwpx` 를 실행하면 검사가 함께 돈다.
   경고가 나오면 **본문을 고쳐** 다시 실행한다(경고를 끄지 않는다)
5. **결과 확인** — 생성된 경로를 보고한다. `--preview 미리보기.html`을 붙이면 근사 미리보기도
   같이 나온다(글꼴·줄바꿈·도식 연결선은 한글에서 최종 확인)
6. **반복** — 사용자 피드백을 반영해 3~5를 되풀이한다

범위가 큰 경우(장별 5쪽 이상) 섹션을 나눠 순차 작성·검토를 제안한다.

## 레벨 체계

본문 각 줄은 **줄머리 마커 + 공백 한 칸 + 내용**이다.

| 마커 | 스타일 | 자동 부여 | 역할 |
|---|---|---|---|
| `#` | 로마자 | `Ⅰ. Ⅱ.` | 큰 타이틀 (장) |
| `##` | 숫자 | `1. 2.` | 작은 타이틀 (절) |
| `□` | 네모 | `□` | 주제 제시 |
| `○` | 원 | `○` | 본문 (주요) |
| `-` | 하이픈 | `-` | 본문 (설명) |
| `·` | 점 | `·` | 본문 (세부·구체) |
| `※` | 참고 | `※` | 용어·사례·근거 보조 |
| (빈 줄) | | | 블록 구분 |

```
# 서론
## 배경 및 필요성
□ 【배경 1】 정책 수요 변화
○ (1) 고령화 심화
- 65세 이상 인구 비율 20% 초과
- 돌봄 서비스 수요 급증
· 고독사 위험군 모니터링 대상 전년 대비 2.3배 확대
※ 통계청, 2024
```

마커 뒤에는 **공백 한 칸**. 그래서 `-3% 감소` 같은 표현은 마커로 오인되지 않는다.
레벨별 상세 용법은 `reference/level-system.md`.

## 자동 부여 vs 직접 입력 (가장 실수하기 쉬운 부분)

**자동 부여 — 본문에 겹쳐 쓰지 말 것**
- 글머리 기호 `□ ○ - · ※`(줄머리 마커가 곧 그것이다), 자동 번호 `Ⅰ. Ⅱ.` `1. 2.`

**직접 입력 — 마커 뒤에 그대로 쓸 것**
- 네모의 `【】` 머릿글 → `□ 【전환 3】 단일 중앙 AI 의존`
- 원의 `()` 머릿글 → `○ (1축) 선제적·수요중심 AI 도입`
- 그 외 본문 텍스트 전부

`□ □ 【배경】…`처럼 겹쳐 쓰면 검사가 "마커가 중복 입력됨"으로 잡아낸다.
잘못된 예와 올바른 예는 `reference/examples.md`.

## 계층 균형 규칙

- `##`(숫자) 아래 **네모 2개 이상**, `□` 아래 **원 2개 이상**, `○` 아래 **하이픈 2개 이상**
- 하이픈 이하(점·참고)는 균형 규칙 미적용

**이 규칙은 도구가 검사한다.** 어긋나면 `[경고:balance]`로 나온다.
옳은 구조와 피해야 할 구조는 `reference/hierarchy-rules.md`.

## 서술 형식 (개조식)

- 한 항목에 **단문 1개**면 끝 **온점 생략**, **두 문장 이상**이면 문장 사이·끝에 **온점**
- 한 항목은 원칙적으로 한 줄. 경어체·종결 어미 금지
- 내용은 구체적으로, 표현은 간결하게. 전문 용어는 필요하면 짧게 풀이

온점 규칙도 검사 대상이다(`[경고:period]`).

## 머릿글 규칙

- **네모(`□`)**: `【카테고리 N】 키워드` — 예: `□ 【쟁점 1】 개인정보 보호 범위`
- **원(`○`)**: `(축/번호) 키워드` — 예: `○ (1축) 선제적·수요중심 AI 도입`
- 그 외 레벨은 머릿글 규칙 없음

이 규칙도 검사한다(`[경고:head]`). 규칙 자체는 `profile.json`의 `rules.head_pattern`에 있다.

## 각주

근거·출처는 본문에 `(통계청, 2024)`로 적지 말고 **각주로 단다.** 근거가 되는 말 바로
뒤에 `[^라벨]`을 붙이고, 내용은 아무 데나 `[^라벨]: …` 줄로 적는다.

```
○ 노인 빈곤율은 40.4%로 OECD 최고 수준이다[^1]

[^1]: 통계청(2024), 「가계금융복지조사」.
```

한글의 **진짜 각주**(쪽 아래 + 자동 번호)로 들어가고, 글씨는 **8pt 회색**이다.
라벨은 이름표일 뿐이고 인쇄되는 번호는 한글이 문서 순서대로 매긴다.

**번호를 놓는 자리** — 이 네 가지를 지킨다. 따옴표 규칙 말고는 어기면
`[경고:footnote]`가 뜬다.

| 규칙 | 맞는 예 | 틀린 예 |
|---|---|---|
| 앞말에 붙여 쓴다 | `40.4%다[^1]` | `40.4%다 [^1]` |
| 문장 전체의 근거면 마침표 **앞** | `…이어졌다[^2].` | `…이어졌다.[^2]` |
| 인용문 자체가 대상이면 따옴표 **안** | `"…구조적 문제다[^3]"라고` | — 도구가 검사하지 않는다 |
| 낱말 하나면 그 낱말 뒤 | `기초연금[^4]은` | 문장 끝까지 끌고 가기 |

따옴표는 **각주가 무엇을 가리키는지**로 갈린다. 인용문 자체의 출처·근거이면 닫는
따옴표 **안**(`"…구조적 문제다[^3]"라고 했다`), 인용을 쓴 문장 쪽의 근거이면 따옴표
밖(`"구조적 문제"[^4]라는 진단`)이다. 도구는 이 둘을 구분하지 못해 검사하지 않는다.
인용문의 출처를 다는 경우가 대부분이므로, 헷갈리면 **따옴표 안**이다.

제목(`#`, `##`), 표 안, 도식 상자 안에는 달지 않는다. 표에 주석이 필요하면 표 아래에
`※ ` 줄을 쓴다.

**출처를 지어내지 않는다.** 확인한 자료만 각주로 달고, 확인하지 못했으면
`[확인 필요]`로 남겨 사용자에게 묻는다. 자세한 규칙은 `reference/footnote.md`.

## 표·그림·도식

**표** — 앞뒤에 빈 줄을 두고 파이프로 쓴다. 첫 행이 머리행(파란 배경·흰 볼드).

```
| 구분 | 2023 | 2024 |
|---|---|---|
| A사업 | 100 | 120 |
```

**그림** — `![](파일경로.png)`. 기본 가로 120mm, 비율 자동. **실제 있는 파일만** 넣는다.

**도식** — 한글에서 **편집 가능한 표**로 들어간다. 네 가지가 있다.

| 유형 | 쓸 곳 | 쓰는 법 |
|---|---|---|
| `type=org` | 조직도·체계도·전달체계 | 2칸 들여쓰기 트리 |
| `type=flow` | 절차도·흐름도 | `접수 → 검토 → 통보` 한 줄 |
| `type=matrix` | 격자·비교표 | 파이프 표 |
| `type=strategy` | 전략체계도(미션·비전·핵심가치·전략과제) | `단이름 \| 칸 \| 칸` 줄 |

쓰는 법은 `reference/diagram.md`에 전부 있다. 조직도를 예로 들면:

```
:::diagram type=org title="추진 체계"
총괄 {fill=#1F3864 color=#FFFFFF}
  기획부
  운영부
:::
```

**그림·캡처뿐인 도식을 옮길 때**는 에이전트가 직접 그림을 보고 위 형식으로 받아쓴 뒤,
그 블록을 사용자에게 보여 확인받는다. 계층을 추정으로 채우지 않는다.
Mermaid·SVG·HTML 파일이면 `python scripts/capture.py 원본.svg`로 읽는다.

## 실행

```bash
python scripts/build.py input.md -o 보고서.hwpx                    # 검사 + 생성
python scripts/build.py input.md -o 보고서.hwpx --preview 미리보기.html
python scripts/capture.py 조직도.svg --title "조직 체계"           # 도식 가져오기
```

의존성은 `python-hwpx` 하나다(엔진은 `scripts/hwpx_studio/`에 동봉). 한글 프로그램 불필요.

## 실행 직전 체크리스트

도구가 검사하는 항목은 ✔, 사람이 봐야 하는 항목은 ○로 표시했다.

- ○ 반 페이지 분량 미리보기를 제시하고 승인을 받았는가
- ✔ 마커를 본문에 겹쳐 쓰지 않았는가 (`[경고:parser]` `[경고:symbol]`)
- ✔ 온점 처리 (`[경고:period]`)
- ✔ 네모의 `【】`·원의 `()` 머릿글 (`[경고:head]`)
- ✔ 숫자 아래 네모 2개 / 네모 아래 원 2개 / 원 아래 하이픈 2개 (`[경고:balance]`)
- ✔ 중간 레벨을 건너뛰지 않았는가 (`[경고:jump]`)
- ✔ 표·도식 앞뒤 빈 줄 (`[경고:spacing]`)
- ✔ 각주 번호 자리 — 붙여쓰기·마침표 앞·인용부호 뒤·제목 금지 (`[경고:footnote]`)
- ✔ 각주 내용이 빠졌거나 부르지 않은 각주가 없는가 (`[경고:parser]`)
- ○ 각주에 적은 출처를 실제로 확인했는가 (지어내지 않았는가)
- ○ 일반 본문은 하이픈에서 종결, 점은 세부사항에만
- ○ 참고는 본문 흐름과 분리된 보조 정보에만
- ○ 사실 검증 불가한 수치·출처가 남아 있지 않은가
- ○ 도식의 계층·색을 원본에서 확인했는가(추정으로 채우지 않았는가)
