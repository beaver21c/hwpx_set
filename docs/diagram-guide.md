# 도식(조직도·체계도·절차도) 작성 안내

이 문서는 hwpx-studio로 한글(.hwpx) 문서 안에 조직도·체계도·절차도를 넣는 방법을
설명한다. 프로그래밍 지식은 필요 없다.

---

## 1. 클릭으로 그리는가, 글로 쓰는가

**글로 쓴다.** 마우스로 상자를 하나씩 놓고 선을 잇는 방식이 아니라, 메모장에 목록을
쓰듯 구조를 적으면 도구가 배치와 연결선을 자동으로 계산해 한글 문서에 넣는다.

| 방식 | 한글 프로그램에서 직접 그리기 | hwpx-studio(이 도구) |
|---|---|---|
| 작업 | 표 삽입 → 셀 병합 → 셀마다 테두리 끄고 켜기 → 글자 입력, 또는 그리기 개체(사각형·선)를 하나씩 배치·정렬 | 들여쓰기 목록 6~10줄 작성 |
| 소요 | 상자 5개 기준 수십 회 클릭 [일반적 경험] | 타자 1분 |
| 수정 | 상자 추가 시 주변 정렬 다시 | 목록에 한 줄 추가 후 재생성 |
| 결과물 | 표 또는 그리기 개체 | **표**(기본) 또는 그림 |
| AI 활용 | 불가 | 어떤 AI에든 "아래 형식으로 조직도 써줘"로 생성 가능 |

생성된 도식은 한글에서 **보통의 표**이므로, 이후 한글에서 글자를 고치거나 행을
추가하는 것은 평소 표 편집과 같다.

---

## 2. 기본 형식

보고서 본문 텍스트 안에 `:::diagram` 으로 시작해 `:::` 으로 끝나는 블록을 넣는다.

### 2.1 조직도·체계도 (`type=org`)

위에서 아래로 내려가는 계층 구조. **들여쓰기 2칸**이 한 단계 아래를 뜻한다.

```
:::diagram type=org title="조직 체계"
대표
  기획부
    기획팀
    예산팀
  운영부
  연구부
:::
```

결과: 맨 위 "대표", 그 아래 가로로 기획부·운영부·연구부, 기획부 아래 기획팀·예산팀.
연결선은 자동이며 **상자의 가운데**에서 내려온다.

체계도(예: 추진 체계, 전달 체계)도 같은 형식으로 쓴다. 최상위에 총괄 기구, 아래에
하위 기구를 나열하면 된다.

**상자가 많을 때(실·국이 8개 넘는 조직도)** 는 가로로 늘어놓으면 글자가 뭉개진다.
그럴 때는 도구가 **세로 목록형**으로 알아서 바꾼다. 직접 지정하려면 `layout=side`.

```
:::diagram type=org layout=side title="세로 목록형 조직도"
원장
  기획조정실
    기획팀
    예산팀
  감사실
:::
```

세로 목록형은 상자를 한 줄에 하나씩 쌓고 단계마다 오른쪽으로 들여쓴다.
**상자가 늘어도 폭이 넓어지지 않으므로**, 몇 개든 한 쪽에 들어간다.
가로 배치를 고집하려면 `layout=wide`(또는 `width`를 늘릴 것).

### 2.2 절차도·흐름도 (`type=flow`)

왼쪽에서 오른쪽(기본) 또는 위에서 아래로 흐르는 단계.

```
:::diagram type=flow
접수 → 검토 → 심의 → 통보
:::
```

세로 배치: `:::diagram type=flow direction=down`
화살표는 `→`, `->`, `=>`, `>` 무엇을 써도 인식한다.

### 2.3 전략체계도 (`type=strategy`)

미션·비전·핵심가치·전략방향·전략과제가 단(段)으로 쌓이는, 공공기관 경영전략
체계도에서 흔한 모양이다. **왼쪽에 단 이름, 오른쪽에 그 단의 칸들**을 `|`로 나눠 쓴다.

```
:::diagram type=strategy title="경영전략 체계도"
미션 | 소비생활에 가치와 신뢰를 더하여 국민의 삶의 질 향상에 기여한다
비전 | 공정하고 안전한 소비환경을 만드는 국민의 기관
핵심가치 | 공감 | 안전 | 공정 | 신뢰
4대 전략방향 | 분쟁해결 | 안전환경 | 거래환경 | 혁신경영
12대 전략과제 | 피해의 실질적 회복 | 위해요인 탐지 | 실용적 정보제공 | 운영 효율성 제고
| 선제적 대응 강화 | 사각지대 개선 | 거래 감시 강화 | ESG 경영체계 강화
:::
```

- **라벨 없이 `|`로 시작한 줄은 위 단의 다음 줄**이다. 라벨 칸이 그만큼 세로로 늘어난다
  (위 예의 12대 전략과제가 두 줄을 차지한다)
- 칸이 하나뿐인 단(미션·비전)은 가로 전체를 차지한다
- 연결선은 자동이다. 갈래가 갈리는 곳(1칸 → 4칸)에만 가로선이 생기고,
  칸 수가 같으면 세로선만 내려온다
- 단 이름에 `{link=none}`을 붙이면 **그 단 위쪽 연결선을 그리지 않는다**(붙여 놓을 때)
- 칸에 `{border=none}`을 붙이면 상자 없이 **글자만** 놓인다(경영목표 수치처럼)
- 색은 §3과 같다. 라벨과 칸 모두 `{fill=… color=…}`를 쓸 수 있고,
  `label_width=24`(mm)로 라벨 열 폭을 조절한다

`examples/input_strategy.md`에 색까지 지정한 전체 예시가 있다.

### 2.4 매트릭스·비교표 (`type=matrix`)

행·열로 구분되는 격자. 첫 행·첫 열이 제목 칸이 된다.

```
:::diagram type=matrix title="역할 분담"
| | 중앙 | 지방 |
| 기획 | 본부 | 지역본부 |
| 집행 | 사업단 | 현장사무소 |
:::
```

## 3. 색을 지정하는 방법

원본 도식의 색을 그대로 살리고 싶을 때는 상자 이름 뒤에 `{ }`로 적는다.

```
:::diagram type=org title="추진 체계"
추진단 {fill=#C00000 color=#FFFFFF}
  기획반 {fill=#2E75B6 color=#FFFFFF}
  운영반 {fill=#70AD47 color=#FFFFFF}
  감사반 {fill=#FFF2CC border=#BF8F00 link=dash link_color=#808080}
:::
```

| 속성 | 뜻 | 예 |
|---|---|---|
| `fill` | 상자 채움색 | `fill=#DCE6F1` |
| `color` | 글자색 | `color=#FFFFFF` |
| `border` | 상자 테두리색. `none`이면 테두리 없이 글자만 | `border=#BF8F00`, `border=none` |
| `link` | **부모에서 이 상자로 내려오는 연결선**의 종류. `none`이면 안 그린다 | `link=dash`, `link=none` |
| `link_color` | 그 연결선의 색 | `link_color=#808080` |

- 색은 `#RRGGBB`, `#RGB` 어느 쪽이든 된다(`#fff` = `#FFFFFF`). 알아볼 수 없는 값은
  **무시하고 프로파일 기본색을 쓴다** — 오타 때문에 생성이 실패하지는 않는다
- 선 종류: `solid`(기본) `dash` `dot` `dashdot` `dashdotdot` `longdash`.
  `점선`·`실선`이라고 써도 된다
- 속성 구분은 공백이든 쉼표든 상관없다: `{fill=#EEE, color=#333}`
- 절차도(`flow`)의 각 단계, 매트릭스(`matrix`)의 각 칸에도 똑같이 쓸 수 있다

### 도식 하나만 통째로 다른 색으로

블록 첫 줄에 쓰면 그 도식 전체에 적용된다(상자마다 쓸 필요 없다).

```
:::diagram type=org box_fill=#F2F2F2 root_fill=#404040 line_color=#808080 line_style=dash
```

`box_fill` `box_border` `box_color` `root_fill` `root_color` `line_color` `line_style`을
쓸 수 있고, 프로파일 기본값을 그 블록에서만 덮어쓴다.

> **연결선 색·종류가 적용되는 범위**: 한글 표는 한 셀의 네 변이 같은 선 종류를
> 공유한다. 그래서 `link=dash`는 그 자식으로 내려가는 **구간**(자식 위 세로선과 바로
> 앞 가로선)에 적용되고, 형제들이 함께 쓰는 가로 버스 전체가 점선이 되지는 않는다.

## 4. 남의 도식 가져오기 (`capture`)

이미 있는 도식을 처음부터 다시 타자할 필요는 없다. 웹·문서에 있는 도식을 읽어
§2~3 형식의 블록으로 바꿔 준다.

```bash
hwpx-studio capture 조직도.svg --title "조직 체계"        # 화면에 블록 출력
hwpx-studio capture 조직도.svg -o 도식.txt                 # 파일로 저장
hwpx-studio capture 도식.md --hwpx 도식.hwpx               # 한글 문서까지 한 번에
pbpaste | hwpx-studio capture -                            # 붙여 넣은 내용을 그대로
```

| 읽을 수 있는 것 | 어디서 나오나 | 구조 | 색 |
|---|---|---|---|
| **Mermaid** (`flowchart TD` / `graph LR`) | 위키·GitHub·노션, AI에게 "머메이드로 그려줘" | 정확 | `style`·`classDef`에 적힌 그대로 |
| **SVG** | 웹 페이지에서 [다른 이름으로 저장], 발표자료에서 복사 | 연결선을 읽어 세움 | `fill`·`stroke` 그대로 |
| **HTML·마크다운** | 웹 문서 저장본 | 안에 든 SVG나 mermaid 블록을 찾아 읽음 | 위와 같음 |

- 색은 **원본에 적힌 값을 그대로** 가져온다(눈대중이 아니다)
- 점선(`-.->`, `stroke-dasharray`)은 `link=dash`로 옮긴다
- SVG에 연결선이 없으면 **상자의 높이로 계층을 추정**하고 그 사실을 경고로 알린다
- 한 상자에 들어오는 연결선이 여럿이면(협력·자문 관계) 첫 번째만 계층으로 쓰고
  나머지는 경고로 알린다 — 표 도식은 상자마다 부모가 하나다
- **결과는 반드시 눈으로 확인할 것.** 나온 블록은 그냥 텍스트라서, 틀린 줄만
  고쳐 쓰면 된다. 이것이 이 도구가 중간에 텍스트를 두는 이유다

### 그림(PNG·스캔)은?

아직 못 읽는다. 다만 **AI에게 그림을 보여 주고 §2~3 형식으로 받아쓰게 하면** 된다.
그 결과를 `hwpx-studio build`에 넣으면 같은 결과가 나온다. 프롬프트 예:

> 이 도식을 아래 형식으로 옮겨 줘. 상자 색은 `{fill=#RRGGBB color=#RRGGBB}`로 함께 적어 줘.
> (여기에 §2·§3 예시를 붙여 넣기)

경영전략 체계도처럼 **단이 쌓인 그림**이면 §2.3의 `type=strategy` 예시를 보여 주면 된다.
그림을 읽는 것은 AI가, 표로 그리는 것은 이 도구가 맡는 셈이다.

## 5. 옵션

| 옵션 | 값 | 설명 |
|---|---|---|
| `title="…"` | 문자열 | 도식 아래에 붙는 제목 |
| `render=table` (기본) | table / image | table: 한글에서 편집 가능한 표. image: PNG로 그려 삽입 |
| `direction=right` | right / down | flow 전용. 진행 방향 |
| `layout=side` | side / wide | org 전용. side=세로 목록형, wide=가로 고정. 안 쓰면 폭에 맞춰 자동 |
| `label_width=24` | mm | strategy 전용. 왼쪽 라벨 열 폭 |
| `width=160` | mm | 도식 최대 폭. 넘치면 자동 축소, 그래도 넘치면 image로 전환 |

상자 색·선 굵기·글자 크기의 **기본값**은 **프로파일(JSON)의 `diagram` 항목**에서 한 번만
정한다. 문서 전체의 도식이 같은 모양으로 나오고, 위 §3의 지정이 있으면 그쪽이 이긴다.

| 프로파일 항목 | 뜻 |
|---|---|
| `box_fill` / `box_border` | 상자 채움색 / 테두리색 |
| `root_fill` / `root_color` | 최상위 상자의 채움색 / 글자색 |
| `col_width_mm` / `col_gap_mm` | 상자 폭 / 상자 사이 간격 |
| `row_height_mm` / `row_gap_mm` | 상자 높이 / 단계 사이 간격 |
| `max_width_mm` | 최대 폭(넘으면 축소 후 이미지 폴백) |
| `grid_resolution` | 상자 하나가 차지하는 열 수(짝수, 기본 6). 클수록 연결선 위치가 정밀해지지만 표의 열이 많아진다 |

## 6. 어떻게 그려지는가(참고)

표 방식은 **균일한 폭의 열**로 격자를 만든다.

- 상자 = `grid_resolution`개의 열을 병합한 셀(채움색 + 4변 테두리)
- 병합 구간의 한가운데가 곧 열 경계 → 그 경계가 상자의 중심선
- 세로 연결선 = 그 경계에 해당하는 셀의 **오른쪽 변** 테두리
- 가로 버스 = 자식들 중심 사이 셀들의 **위쪽 변** 테두리
- 나머지 셀 = 테두리 없는 투명 셀

부모의 중심은 자식 중심들의 중간값이라 열 폭이 균일하면 항상 유효한 열 경계에
떨어진다. 그래서 깊이·자식 수와 무관하게 연결선이 상자 가운데에 맞는다.

가로 버스는 연결 행의 **위쪽 변**에 그린다. 그 위치가 부모 세로선이 끝나는 경계와
같아서 선이 끊기지 않는다(아래쪽 변에 그리면 한 행만큼 어긋난다).

## 7. 잘 안 될 때

| 증상 | 원인 | 조치 |
|---|---|---|
| 한 줄이 같은 단계로 붙어 나옴 | 들여쓰기가 일정하지 않음(탭·1칸·3칸 혼용) | 2칸 공백으로 통일 |
| 가로가 잘려 보임 | 같은 단계의 상자가 너무 많음 | 그대로 두면 세로 목록형으로 자동 전환된다. 가로를 원하면 `width` 늘리기, 일부를 하위로 내리기, 또는 `render=image` |
| 연결선이 안 보임 | 한 변 테두리 자체는 한글에서 표시되는 것을 확인했다. 버전·뷰어에 따른 차이가 의심되면 | `render=image` 로 전환 |
| 화살표가 필요함 | table 방식은 직선만 지원 | `render=image` 사용, 또는 flow의 `→` 문자 활용 |
| 지정한 색이 안 나옴 | 색 표기를 못 알아봄(`하늘색`, `rgb(0,0,0)` 등) | `#RRGGBB`로 쓸 것 |
| 상자 이름에 `{`가 들어가야 함 | 속성 블록으로 오해됨 | 이름 끝이 아닌 곳에 두거나 `{ }` 대신 다른 기호 사용 |
| `capture`가 상자를 못 찾음 | 형식 자동 판별 실패 | `--kind mermaid\|svg\|html`로 직접 지정 |
| `capture` 계층이 뒤죽박죽 | SVG에 연결선이 없어 높이로 추정함 | 나온 블록의 들여쓰기를 손으로 고칠 것 |
| 상자 글자가 두 줄로 꺾임 | 이름이 셀 폭보다 김 | 프로파일 `diagram.col_width_mm` 늘리기 또는 이름 줄이기 |
| 이미지 도식의 한글이 네모로 나옴 | matplotlib에 한글 글꼴 없음 | `apt install fonts-nanum` 또는 `pip install koreanize-matplotlib` 후 재실행 |
| `render=image`인데 표로 나옴 | matplotlib 미설치 | `pip install hwpx-studio[image]` (경고 메시지로도 안내된다) |

## 8. 한글에서 직접 그릴 때(참고)

이 도구 없이 한글 프로그램에서 같은 도식을 만들려면 일반적으로 두 가지 방법을 쓴다
[일반 지식, 메뉴명·위치는 버전별 상이].

- 표 방식: 표를 넓게 삽입 → 필요한 셀만 남기고 테두리를 없앰 → 연결선이 될 셀의 한 변만
  테두리를 켬 → 상자 셀에 배경색·글자. 이 도구의 `render=table`이 이 과정을 자동화한 것
- 그리기 개체 방식: 사각형과 직선을 개별 삽입 → 위치·크기를 정렬 → 사각형 안에 글자.
  자유롭지만 수정 시 재정렬 필요

둘 다 가능하지만, 보고서에 반복 삽입하거나 조직 개편 때마다 갱신해야 한다면 텍스트
블록으로 관리하는 편이 유리하다.
