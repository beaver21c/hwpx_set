# 각주 다는 법

한글 각주를 **본문에 이어 붙지 않는 진짜 각주**로 만든다. 쪽 아래에 구분선과 함께
붙고, 번호는 한글이 문서 순서대로 매기며, 나중에 문단을 옮기거나 각주를 하나 지워도
번호가 저절로 다시 매겨진다. 본문에 `1)`을 손으로 적는 것과는 다르다.

기본 서식은 **8포인트 회색(`#808080`)** 이다.

---

## 1. 쓰는 법

번호가 들어갈 자리에 `[^라벨]`, 내용은 `[^라벨]: …` 줄로 적는다.

```
□ 노인 빈곤율은 40.4%로 OECD 회원국 가운데 가장 높다[^1]

[^1]: 통계청(2024), 「가계금융복지조사」.
```

- 내용 줄은 **문서 어디에 적어도 된다.** 문단 바로 아래에 적어도 되고, 글 끝에 모아
  두어도 된다. 내용 줄 자체는 본문에 나오지 않는다.
- **라벨은 이름표일 뿐이다.** 인쇄되는 번호는 한글이 문서 순서대로 매긴다.
  `[^통계청]`처럼 이름으로 써도 되고, `[^1]`처럼 숫자로 써도 된다. 숫자로 썼는데
  실제 순서와 어긋나면 검사가 알려 준다.
- 한 문단에 여러 개를 달아도 되고, 각각 제자리에 들어간다.

---

## 2. 번호를 놓는 자리

이 부분이 가장 자주 틀린다. 규칙은 다섯이다. 이 가운데 §2.3·§2.5는 도구가 검사하지
않는다 — 각주가 무엇을 가리키는지는 글쓴이만 알기 때문이다.

### 2.1 앞말에 붙여 쓴다

번호 앞에 빈칸을 두지 않는다. 각주는 **바로 앞의 말**에 대한 것이라는 표시다.

```
○ 재정 지출은 GDP의 12%였다[^1]      ← 맞다
○ 재정 지출은 GDP의 12%였다 [^1]     ← 빈칸이 있다
```

### 2.2 문장 전체의 근거이면 마침표 **앞**에 둔다

국내 학술지와 정부 보고서의 관행이다. 시카고 방식(마침표 뒤)과 다르다.

```
○ 이 추세는 2010년대 내내 이어졌다[^2].     ← 국내 관행(기본값)
○ 이 추세는 2010년대 내내 이어졌다.[^2]     ← 시카고 방식
```

기관 지침이 시카고 방식이면 프로파일에서 바꾼다.

```json
{ "rules": { "footnote_position": "after_period" } }
```

`off`로 두면 마침표 관련 검사를 하지 않는다. 나머지 세 규칙은 그대로 본다.

### 2.3 인용 자체가 각주 대상이면 따옴표 **안**에

각주가 무엇을 가리키는지에 따라 자리가 갈린다.

```
○ 보고서는 "노인 빈곤은 구조적 문제다[^3]"라고 표현했다
   └ 인용문 자체의 출처·근거 → 닫는 따옴표 안

○ 이 표현은 "구조적 문제"[^4]라는 진단과 맥을 같이한다
   └ 인용을 쓴 문장 쪽의 근거 → 따옴표 밖
```

무엇에 대한 각주인지는 글쓴이만 아는 것이라 도구가 대신 판단하지 않는다. 검사도
하지 않는다. 인용문의 출처를 다는 경우가 대부분이므로, 헷갈리면 **따옴표 안**이다.

### 2.4 제목·표·도식에는 달지 않는다

- **제목**(`#`, `##`, 자동 번호가 붙는 레벨)에는 달지 않는다. 목차에 번호가 딸려
  들어간다. 제목이 아니라 그 아래 첫 문단에 단다.
- **표 안**과 **도식 상자 안**에는 애초에 들어가지 않는다. 표·도식 아래 문단에
  달거나, 표 아래에 `※` 줄로 주석을 붙인다.

### 2.5 낱말 하나에 대한 것이면 그 낱말 뒤에

문장 끝까지 끌고 가지 않는다. 무엇에 대한 근거인지가 자리로 드러난다.

```
○ 노인장기요양보험[^4]과 기초연금[^5]은 도입 시기가 다르다
```

## 3. 검사가 잡아 주는 것

`hwpx-studio lint` 또는 웹 앱의 [검사]가 `footnote` 코드로 알려 준다.

| 상황 | 알려 주는 말 |
|---|---|
| 번호 앞에 빈칸 | 앞말에 붙여 쓸 것 |
| 마침표 뒤에 번호 (기본 규칙일 때) | 마침표 앞에 붙일 것 |
| 제목에 각주 | 본문 문단으로 옮길 것 |
| 문단 맨 앞에 번호 | 근거가 되는 말 뒤에 붙일 것 |
| 라벨 숫자와 실제 번호가 다름 | 문서 순서로는 N번째 각주 |

내용이 어긋난 경우는 `parser` 코드로 알려 준다.

| 상황 | 도구의 처리 |
|---|---|
| `[^1]`을 썼는데 `[^1]: …` 줄이 없음 | **본문에 `[^1]`을 그대로 남기고** 알려 준다. 조용히 지우면 각주가 빠진 사실이 산출물에서 보이지 않는다 |
| `[^1]: …` 줄만 있고 본문에서 부르지 않음 | 각주를 만들지 않고 알려 준다 |
| 같은 라벨을 두 번 부름 | 각주 **두 개**를 만들고 알려 준다. 한글에는 각주를 다시 쓰는 기능이 없다 |
| 같은 라벨의 내용 줄이 두 번 | 뒤엣것을 쓰고 알려 준다 |
| 내용이 빈 줄(`[^1]:`) | 빈 각주를 만들고 알려 준다 |

## 4. 서식 바꾸기

프로파일의 `footnote` 블록이다. 기본값은 8pt 회색이다.

| 키 | 기본값 | 뜻 |
|---|---|---|
| `size_pt` | `8` | 글자 크기 |
| `color` | `"#808080"` | 글자색 |
| `font` | `"light"` | `fonts.light` / `fonts.bold` 중 어느 것 |
| `bold` | `false` | 굵게 |
| `line_spacing` | `130` | 줄 간격(%) |
| `align` | `"JUSTIFY"` | 정렬 |
| `name` / `eng_name` | `"각주"` / `"Footnote"` | **바꾸지 말 것.** 한글이 각주 스타일을 이 이름으로 찾는다 |

```json
{ "footnote": { "size_pt": 9, "color": "#595959" } }
```

각주 구분선과 번호 모양(`1)` / `1.` / `주1)`)은 문단 서식이 아니라 구역 설정
(`secPr`의 `footNotePr`)에 들어 있다. 도구는 한글 기본값(`1)`)을 그대로 두며,
바꾸려면 한글에서 각주 영역을 클릭한 뒤 각주/미주 모양 대화상자로 문서 전체를
한 번에 고친다.

---

## 5. 미주는?

넣지 않았다. 정책 보고서에서 미주를 쓰는 일이 드물고, 각주로 충분했다.
넣는다면 `_add_paragraph_with_notes`의 `add_footnote`를 `add_endnote`로 가르는
일 말고도, 각주와 같은 방식으로 **`미주`(`Endnote`) 스타일을 header에 등록**해야
한다. 이름으로 찾지 못하면 한글에서 서식이 깨진다(§6 참조).

---

## 6. 확인된 것

- 만든 문서를 표준 판독기(python-hwpx)로 **다시 읽어** 각주 개수·번호·본문을 확인한다
  (`tests/test_footnote.py`)
- 각주 본문이 실제로 8pt(`height="800"`)·회색(`textColor="#808080"`) charPr을
  가리키는지 header.xml에서 확인한다
- 각주 스타일이 **이름으로** 등록되는지 확인한다. 없으면 python-hwpx가 없는 스타일
  번호(15번)로 떨어지고, 한글에서 각주 서식이 깨진다
- 번호 앞뒤 토막이 서로 다른 run으로 갈라지는지 확인한다(번호 자리가 지켜지는 근거)
- 파이썬 엔진과 브라우저 엔진이 **같은 각주 XML**을 내는지 대조한다
  (`tools/compare_js_python.py`)

한글에서 실제로 열어 쪽 아래에 각주가 붙는 모양은 **사용자가 확인해야 한다.**
CI의 `예제-문서` 아티팩트에 `각주_예제.hwpx`가 들어 있다.
