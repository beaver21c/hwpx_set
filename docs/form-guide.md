# 양식 꾸러미 — 쓰던 한글 양식으로 도구 만들기

기관 보고서틀·기안문·계획서처럼 **서식이 이미 갖춰진 hwpx**를 올리면, 그 양식으로
문서를 찍어 내는 **도구 한 벌**이 나온다. 그 꾸러미를 Claude·GPT·codex에 통째로
주면 AI가 내용을 쓰고 **그 자리에서 한글 파일까지** 만든다.

---

## 1. 왜 이렇게 하나 — 재현이 아니라 보존

이 저장소에는 원래 다른 길이 있었다. 양식을 읽어 **프로파일(JSON)로 옮겨 적고**,
그 프로파일로 문서를 처음부터 짓는 방식이다(`hwpx-studio extract` → `build`).
글꼴·크기·여백처럼 문단 속성에 담기는 것은 잘 옮겨진다.

그런데 한글의 서식에는 문단 속성 **바깥**에 있는 것이 있다.

| 잃는 것 | 어디에 있나 |
|---|---|
| 자동 글머리표(□ ○ -를 한글이 붙여 줌) | `header.xml`의 `paraPr > heading type="BULLET"` |
| 번호매기기(Ⅰ. 1. 가.) | `paraPr > heading type="NUMBER"` + `numberings` |
| 각주 구분선·번호 모양 | 구역 설정 `secPr > footNotePr` |
| 쪽 설정·머리말·표지 | 구역 프리앰블 |
| 글꼴 임베딩 | `fontfaces` |

프로파일은 이것들을 담지 못한다. 그래서 **양식 파일 자체를 템플릿으로 쓰기로** 했다.

```
template.hwpx (올린 양식)
├─ Contents/header.xml     ← 한 바이트도 건드리지 않는다
└─ Contents/section0.xml
   ├─ 앞부분(용지 설정·표지·장 제목)  ← 그대로 둔다
   └─ 본문 문단                        ← 이 부분만 새로 만들어 갈아 끼운다
```

서식이 **재현**되는 것이 아니라 **보존**된다.

## 2. 만드는 법

### 웹에서

[웹 앱](https://beaver21c.github.io/hwpx_set/)의 **① 양식으로 도구 만들기**에
hwpx를 올리고 [해부해서 꾸러미 만들기]를 누른다. 파일은 브라우저 밖으로 나가지
않는다.

- `.zip` — 폴더로 풀어 쓴다(codex·GPT·파이썬)
- `.skill` — Claude에 그대로 올린다

### 파이썬으로

```bash
hwpx-studio formkit 양식.hwpx -o 꾸러미/
hwpx-studio formkit 양식.hwpx --pack 양식.skill
hwpx-studio formkit 양식.hwpx --report-only     # 해부 결과만 보기
```

## 3. 꾸러미에 무엇이 들었나

| 파일 | 하는 일 |
|---|---|
| `template.hwpx` | 올린 양식 원본. **고치지 않는다.** 서식의 원천 |
| `form.json` | 양식 카드 — 레벨별 스타일 번호, 표 골격, 마커, 각주 스타일 |
| `build_form.py` | 마커 텍스트 → 한글 문서 |
| `read_hwpx.py` | 서식 없는 문서 → 마커 텍스트(되돌리기) |
| `SKILL.md` | Claude 스킬 지시문 |
| `AGENTS.md` | codex·GPT 지시문 |
| `README.md` | 사람이 읽는 사용법 |
| `해부보고서.md` | 무엇을 근거로 그렇게 보았는지 |
| `예시.md` | 이 양식 마커로 쓴 짧은 예시 |

두 파이썬 스크립트는 **표준 라이브러리만** 쓴다. 설치할 것이 없어 AI의 코드
실행 환경에서 그냥 돈다.

## 4. 쓰는 법

```bash
python build_form.py 원고.md -o 결과.hwpx
python build_form.py 원고.md --check-only     # 입력 검사만
python build_form.py --markers                # 이 양식의 마커 목록
```

입력 문법은 양식마다 마커만 다르고 나머지는 같다.

```
(빈 줄)             문단 사이 간격
| 구분 | 값 |       표. 첫 행이 머리행. |---| 줄은 무시
[표: 제목]          바로 다음 표의 제목
{cols=30,35,35}     바로 다음 표의 열 너비 백분율
셀 안 <br>          셀 안에서 줄 나눔
앞말[^1]            각주 번호 자리
[^1]: 내용          각주 내용(문서 어디에 적어도 된다)
```

---

## 5. 마커는 어떻게 정해지나

해부기가 문단을 (스타일, 문단모양, 글자모양)으로 묶고, 묶음마다 마커를 정한다.
근거는 셋이고 순서가 있다.

1. **한글이 붙이는 글머리표** — `paraPr`에 `heading type="BULLET"`이 걸려 있으면
   그 기호를 마커로 쓴다. 이때 본문 텍스트에는 기호를 **넣지 않는다**(한글이 붙인다)
2. **한글이 붙이는 번호** — `heading type="NUMBER"`이면 `#`, `##` 순으로 준다
3. **본문 텍스트에 적힌 기호** — 문단이 `□ `로 시작하면 그 기호가 마커이고,
   만들 때도 텍스트에 적어 넣는다

셋 다 아니면 근거가 없는 레벨이다. 그래도 입력에서 부를 수단은 있어야 하므로
남는 기호를 **임의로** 준다. 그 사실을 보고서와 `form.json`
(`marker_invented: true`)에 적어 둔다. 이 레벨은 마커로 부르되 기호는 찍히지 않는다.

**마커가 뜻과 다르면 `form.json`의 `levels`를 고치면 된다.** 고친 뒤 다시 빌드하면
그대로 반영된다.

| `form.json`의 키 | 뜻 |
|---|---|
| `marker` | 입력에서 이 레벨을 부르는 기호 |
| `write_marker` | 기호를 본문 텍스트에 적어 넣나 |
| `numbering` | 도구가 번호를 매기나(`AUTO_ROMAN` 등). 한글이 매기면 `null` |
| `auto_bullet` / `auto_number` | 한글이 붙이는 기호·번호(참고용) |
| `style` / `para` / `char` | 양식의 스타일·문단모양·글자모양 번호 |

## 6. 검사 세 층

빌더는 파일을 만들기 전에 세 번 본다.

| 층 | 보는 것 | 걸리면 |
|---|---|---|
| 1층 입력 | 마커 겹침, 표 칸 수, 각주 짝, 표 앞뒤 빈 줄, 레벨 건너뜀 | 알리고 계속(`--strict`면 멈춤) |
| 2층 구조 | 양식에 없는 스타일·문단모양·글자모양·테두리 번호, 이중 기호 | **멈춘다.** 파일을 만들지 않는다 |
| 3층 산출물 | zip 무결성, 모든 XML이 파싱되는지 | 오류를 알린다 |

2층이 중요하다. 양식에 없는 번호를 가리키는 문서는 한글에서 서식이 깨진다.
그 상태로 파일을 남기지 않는다.

## 7. 이미 있는 문서를 이 양식으로

AI가 뽑아냈거나 손으로 대충 쓴 hwpx는 되돌린 뒤 다시 만든다.

```bash
python read_hwpx.py 받은문서.hwpx -o 원고.md --report 추정근거.md
python build_form.py 원고.md -o 결과.hwpx
```

되돌리기는 **추정**이다. 서식이 없는 문서에는 '이건 2단계'라는 표시가 없으니
줄머리 기호·번호·글자 크기를 근거로 삼는다. `추정근거.md`에 단계마다 무엇을
근거로 보았는지 적힌다. 웹에서는 **③ 서식 없는 문서를 양식에 맞추기**가 같은 일을
한다.

- 표는 파이프 표로 되돌아온다
- 각주는 `[^n]`과 `[^n]:` 줄로 되돌아오고, 번호는 문서 순서대로 다시 매겨진다
- **그림은 읽지 못한다.** `[그림 자리]`로 남는다. 조직도·절차도라면 그림을 보고
  도식 블록으로 옮겨 적어야 한다

## 8. 확인된 것

- 만든 문서의 `header.xml`이 양식과 **바이트까지 같은지** 확인한다
- 용지 설정(`secPr`)이 든 앞부분이 그대로 남는지 확인한다
- 한글이 기호를 붙이는 양식에서 본문에 기호가 **들어가지 않는지**, 기호가 텍스트에
  적힌 양식에서는 **들어가는지** 확인한다
- 양식에 없는 스타일 번호를 넣으면 파일이 **만들어지지 않는지** 확인한다
- 만든 문서를 표준 판독기(python-hwpx)로 **다시 읽어** 표·각주를 확인한다
- 마커 텍스트 → hwpx → 마커 텍스트 **왕복**이 글자까지 같은지 확인한다
- 파이썬 해부기와 브라우저 해부기가 **같은 `form.json`**을, 두 되돌리기가
  **같은 마커 텍스트**를 내는지 대조한다(`tools/compare_js_python.py`)
- 브라우저가 만든 꾸러미를 풀어 그 안의 `build_form.py`를 실제로 돌려 본다

한글에서 실제로 열어 보는 일은 이 가운데 어느 것도 대신하지 못한다.
**만든 문서는 한 번 열어 볼 것.**

## 9. 못 하는 것

- **그림·글상자·차트는 옮기지 않는다.** 양식에 있던 것은 프리앰블에 들어 있으면
  남고, 본문 자리에 있던 것은 사라진다
- **구역이 여러 개인 양식**은 첫 구역만 본문으로 쓴다. 나머지 구역은 템플릿에
  그대로 남는다
- **표 안 각주**는 넣지 못한다(한글도 다루기 까다롭다). 표 아래 문단에 단다
- 각주 구분선과 번호 모양(`1)` / `1.` / `주1)`)은 구역 설정에 있어 양식의 값을
  그대로 쓴다. 바꾸려면 한글에서 각주/미주 모양 대화상자로 고친다
